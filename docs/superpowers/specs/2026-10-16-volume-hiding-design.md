# 分卷隐写（自动分卷）设计文档

- 日期：2026-10-16
- 状态：已与用户逐节确认，待实施
- 范围：为 SteganographierGUI 新增「自动分卷隐写」功能，同时适配 CLI 与 GUI
- 前置阅读：仓库 `AGENTS.md`（开发规范、构建命令、发布流程）已通读

## 1. 背景与目标

数十 GB 的文件夹目前需要人工"先分卷压缩、再逐个隐写"，并且中间产物（临时 zip + 输出视频）会让磁盘峰值占用约为原内容的 3 倍。本功能让程序一次性完成"按上限分卷 → 逐卷隐写 → 清理中间产物"，把接收端保持在本程序一贯的简单流程上。

**目标**

1. 一个操作（GUI 勾选 / CLI 加一个参数）完成大文件夹的多视频隐写。
2. 磁盘峰值 ≈ 原内容 + 已完成输出 + 2×单卷上限（不再出现全量 ×2 的中间态）。
3. 两条接收路径都可用，由发送者选择：
   - **模式 A（默认）· 独立压缩包**：每个视频内是一份完整 zip，改后缀即可单独解压，全部解到同一文件夹自动拼回。
   - **模式 C · 真分卷**：整份内容被切成 `.zip.001…00N`，接收端用 7-Zip/Bandizip/新版 WinRAR 打开 `.001` 一次性合并解压。
4. 不改变任何现有行为：未启用分卷时，隐写/解除隐写的代码路径与输出结果逐字节一致。

## 2. 术语与硬性契约

| 术语 | 定义 |
|---|---|
| 上限 V | 用户设定值，**每个输出视频文件**的大小上限（含外壳视频） |
| 卷预算 B | 单卷可容纳的 zip 大小；`B = V − 外壳大小 − 1 MiB 余量`（余量覆盖 free 原子头 8/16 字节、64–256 字节随机垫、zip 注释、中央目录增长估算误差） |
| 卷 | 一批内容打包成一份隐写载荷，隐写进一个视频；一卷一个视频 |
| 部件 | 模式 C 中真分卷的单个分片文件（`xxx.zip.001` 等） |

**契约**

- C1：每个输出视频 ≤ V。仅存一处显式例外并提前提示：mkv 模式受 2 GB 硬限制，预算会向下钳制到 2 GiB 以内（见 §10）。
- C2：未启用分卷 → 全流程行为不变（回归红线，见 §13）。
- C3：分卷只影响隐写侧；解除隐写（`reveal_file` / `-r` / `-rd`）零改动，对每个分卷视频照常可用。

## 3. 总体架构

```
GUI 勾选/输入 ─┐
               ├─→ hide_volumized() 编排器
CLI 参数 ──────┘        │
                        ├─ 1. 枚举输入条目（沿用排除临时包的逻辑）＋规划卷（plan_volumes，纯函数）
                        ├─ 2. 生成封面序列（复用现有 随机/时长顺序/名称顺序 模式；不足则循环复用并警告）
                        └─ 3. 逐卷循环：压缩 → 隐写 → 立即删临时文件
                                 │            │
                                 │            └─ _embed_zip_into_video()（自 hide_file 抽出的共用嵌入段）
                                 └─ 模式 A：pyzipper/zipfile 写卷 zip（复用现有随机化习惯）
                                    模式 C：7z.exe 一次生成 .zip.001…（tools/7z.exe 23.01）
```

组件边界：

- `plan_volumes()`：纯逻辑，输入条目清单与各卷预算，输出卷计划（哪些文件/哪些字节区间进哪一卷）。可独立测试。
- `_embed_zip_into_video()`：把"cover + free 原子 + zip"写到输出视频。单文件流程与分卷流程共用，保证两种路径的嵌入结构完全一致。
- `hide_volumized()`：编排器，负责空间清理、日志、进度、失败语义。
- GUI/CLI 只做参数解析与路由，不含卷逻辑。

## 4. 模式 A：独立压缩包

- 每卷 = 一份**完整、可独立解压**的 zip，与现有单卷 zip 的内部结构、加密方式、随机化习惯完全一致（加密时 AES + 仅存储；无密码时 DEFLATE + 随机等级；卷内条目随机打乱；随机时间戳；zip 注释改为记录**该卷内容**的 SHA-256/时间戳）。
- **装包规则**：条目按（打乱后的）顺序依次装包；装不下当前卷剩余空间就滚到下一卷**整装**。普通文件永远不会被切开。
- **切块规则**（仅当单文件自身 + 开销 > 满卷预算时）：
  - 按社区 `.001/.002` 惯例跨卷切块；若当前卷剩余 < 16 MiB 则跳过（避免碎片），从下一卷开始切。
  - 部件名 = `原相对路径名.001`（总片数 >999 时按总位数补零），在卷内保持原相对路径。
  - 凡卷内含有某文件 `.001` 部件的卷，附一个 `合并说明.txt`（UTF-8 带 BOM），内含可直接复制的 `copy /b` 命令与 7-Zip「文件→合并文件」替代方案。
- **命名**：`原名_hidden_1of5.mp4` / `外壳名_1of5.mp4` / `随机名_1of5.mp4`。只产出 1 卷时不加 `ofN`，走现有标准路径（含现有 `_hidden_1` 后缀行为）。
- **接收流程**：每个视频改后缀为 `.zip` → 解压 → 全部解到同一文件夹即自动拼回（部分卷也可单独解出其内容）。含切块件时按 `合并说明.txt` 合并。

## 5. 模式 C：真分卷

- **生成**：调用捆绑的 `tools/7z.exe`（23.01）一次性把整个输入生成分卷 zip：
  `7z a -tzip -v{部件尺寸} [-p密码 -mem=AES256] -mx{0 或 5} <basename>_hidden.zip <输入>`
  - 部件尺寸 = `V − max(本次轮换涉及的候选外壳尺寸) − 1 MiB`（保守统一值）。
  - 有密码：AES-256 + 仅存储（与现有加密哲学一致）；无密码：DEFLATE。
  - 确切参数组合（`-v` 单位写法、`-mem` 生效性、命名 `.zip.001` 形态）以实施首日 spike 实测为准（见 §15），若有差异在此文档补充修订。
  - **2026-10-16 spike 结论**：`-tzip -v{n}b` 命名 `.zip.001…`；`-p` + `-mem=AES256` 组合有效，7z 自解与 WinRAR 7.23 直开 `.001` 均实测通过。另发现并修复：仓库缺 `tools/7z.dll`，导致捆绑 7z.exe 完全不可用（详见 §15 第 5 条）。
- **每卷隐写**：生成一个**不加密的"载具 zip"**（用现有压缩函数生成，保留随机化），内容 = 第 k 个部件文件 + `解压说明.txt`（每卷都放）。载具只是运输层，避免接收端按卷重复输密码。
- **密码策略**：密码只加在真分卷上；接收端在打开 `.001` 合并解压时输入一次。
- **命名**：与模式 A 相同（`_kofN`）。
- **取舍（如实记录）**：
  - 必须全部卷齐全才能解压，无法部分解压；
  - 接收门槛略高：旧版 WinRAR 打不开 `.zip.001`（需 7-Zip/Bandizip/新版 WinRAR，兼容矩阵见 §12）；
  - 分卷内部结构为标准 7z 产物，放弃卷内"随机顺序/随机时间戳"指纹习惯（外壳轮换仍在）。
- **接收流程**：每个视频改后缀为 `.zip` → 解压得到 `xxx_hidden.zip.001…00N` → 全部分卷放同一文件夹 → 用 7-Zip/Bandizip/新版 WinRAR 打开 `.001` → 一次性解出全部内容（此时输入密码）。

## 6. 空间与流水线

```
规划 N 卷 → for k = 1..N:
  压缩第 k 卷 → 临时 zip（落输入的同级目录；沿用 build_temp_archive_path 的防自包含约束）
  隐写第 k 卷 → 输出视频 k
  立即删除临时 zip（try/finally；删除失败只记日志、不掩盖真实错误——沿用现有习惯）
```

- 峰值 ≈ 原内容 + 已完成输出 + 2×单卷上限。示例：30 GB 内容、4 GB 上限 → 峰值 ≈ 68 GB（现状 90 GB）。
- 中途失败：立即停止；清理当前临时卷；**已完成卷保留**；日志指明断点和完成清单，便于续传（用户手动从剩余内容继续，不做断点续传）。
- 进度：模式 A 规划后即知 N；模式 C 在分卷生成完成后得到 N（生成阶段显示 7z 阶段进度）。GUI 全局进度 = (已完成卷数 + 当前卷内部进度) / N；每卷日志三行（开始压缩 / 压缩完成开始隐写 / 完成）。
- 封面轮换索引 = 本批次已生成的视频总数（跨输入连续）；候选外壳数量不足时循环复用并在日志/界面明确警告。

## 7. CLI 接口

```bat
steg -i "D:\big" -p "pass" --volume-size 4G
:: → big_hidden_1of5.mp4 … big_hidden_5of5.mp4（在 big 的父目录；封面按名称顺序轮换 cover_video 内全部 mp4）

steg -i "D:\big" --volume-size 4G --volume-mode split
:: → 真分卷模式：每个视频内是 big_hidden.zip.00N 部件 + 解压说明.txt

steg -i "D:\movie.mkv" --volume-size 4000M -t mkv
:: → 单文件超限：模式 A 自动切块；模式 C 直接对单文件分卷
```

- 新增参数：
  - `-vs, --volume-size <值>`：`4G` / `4096M` / 纯数字（= MB）。未提供 → 不启用分卷。
  - `--volume-mode {zip,split}`：`zip` = 模式 A（默认），`split` = 模式 C。
- 约束与互斥：
  - 与 `-r` 互斥（报错提示"分卷仅用于隐写"）；
  - 分卷模式下 `-o` 语义 = 输出**目录**（不存在自动创建）；传了像文件名的值（带扩展名）则报错说明；
  - `-c` 指定单一外壳 → 全部卷共用该外壳（日志警告重复）；未指定 → 按名称顺序轮换 `cover_video` 全部 mp4；
  - `mp4(zarchiver)` 模式不支持分卷 → 明确报错（zarchiver 嵌入会把整包读入内存，不适合大卷）；
  - mkv 模式：预算按 2 GiB 硬限制向下钳制并明确提示（不静默）。
- `-h` 帮助与 README 同步更新。

## 10. 错误处理与边界

| 情形 | 行为 |
|---|---|
| 上限过小（B < 16 MiB） | 报错，提示最小可用上限 |
| 某外壳 ≥ 上限 | 报错并指出具体外壳文件名 |
| 空文件夹 / 全空子目录 | 沿用现有行为 |
| mkv 模式预算 > 2 GiB 硬限制 | 向下钳制 + 明确提示（日志/界面） |
| zarchiver 模式 + 分卷 | 明确报错拒绝 |
| 磁盘写满 / 中途异常 | 停止、清临时文件、保留已完成卷、日志指明断点 |
| 部件数 > 999 | 编号自动加宽位数 |
| 输出重名 | 沿用现有重名策略（已有"隐写输出重名自动改名"勾选/`--auto-rename`） |
| 超长路径、文件被占用 | 与现有一致，不新增处理 |
| 1 卷产出 | 走现有标准路径（不加 `ofN`） |

## 11. 接收端说明文案（写入隐写文件内部）

模式 C 的 `解压说明.txt`（草案，实施时可微调）：

```
【分卷解压说明】
本视频内藏有分卷压缩包的第 k 个分卷（共 N 个），全部内容分散在 N 个视频里。
1. 把每个视频文件的后缀名改为 .zip，用任意解压软件解压，
   得到 xxx_hidden.zip.001 ~ xxx_hidden.zip.00N。
2. 把全部分卷放在同一个文件夹里（解压到同一目录即可）。
3. 用 7-Zip、Bandizip 或新版 WinRAR 打开 xxx_hidden.zip.001，直接解压全部内容。
   如果设置了密码，此时输入。
注意：分卷必须全部齐全才能解压；旧版 WinRAR 打不开 .001 分卷时，请改用 7-Zip 或 Bandizip。
```

模式 A 的 `合并说明.txt`（草案）：

```
【大文件合并说明】
以下文件因为超过单卷上限被切成了多个片段，解压全部视频后请按顺序合并：
copy /b "big.mkv.001"+"big.mkv.002"+"big.mkv.003" "big.mkv"
也可以用 7-Zip：选中 big.mkv.001 → 菜单「文件」→「合并文件」。
```

## 15. 实施首日验证项（Spike）——已实测（2026-10-16）

1. ✅ 命名与参数：`7z a -tzip -v1m -mx=0 -p"…" -mem=AES256` → `arc.zip.001/.002/.003`；`7z l/x` 打开 `.001` 自动合并（`Volumes: 3`），解出内容哈希一致。
2. ✅ pyzipper 流式写入：**必须**用 `zf.setpassword(b"…")` + `zf.zipinfo_cls(arcname)` + `zf.open(zi, "w")`（写模式下 `open(pwd=…)` 参数不生效，改用归档级密码）；实测 AES zip 由 7z 完整解出、哈希一致。
3. ✅ `-bsp1` 进度：stdout 出现 `NN%` 进度行，可按 `(\d+)%` 解析。
4. ✅ WinRAR 7.23 直开 `.zip.001`：`WinRAR.exe x -ibck -inul -p… arc.zip.001 <dest>` exit=0，内容一致。
5. ⚠️ 额外发现并修复：捆绑 `tools/7z.exe` 依赖 `tools/7z.dll`，而该 DLL 自 v1.3.10 起从未入库/入包（7z.exe 一切操作失败："7-Zip 优先解压"一直静默降级，回退到慢速方案）。已补入官方 23.01 x64 `tools/7z.dll`（SHA-256 `77222e81…`），并加入 `scripts/validate-release.ps1` 与 `scripts/smoke-test.ps1` 的必需文件清单。

## 17. 风险记录

| 风险 | 缓解 |
|---|---|
| 7z `-v`/AES 参数细节与预期不符 | 实施首日 spike（§15），文档回填 |
| 旧版 WinRAR 打不开 `.001` | 兼容矩阵 + 说明文案指引 7-Zip/Bandizip；模式 A 为默认 |
| 模式 C 放弃部分随机化指纹 | 记录为已知取舍；需要时可选模式 A |
| 计划期条目开销估算偏差导致卷超限 | 每卷 1 MiB 余量 + 卷关闭后终检（超限则中止并报错，不会产出超限文件） |
| 超长路径叠加 `_kofN` 后缀 | 与现有一致，不新增处理 |
